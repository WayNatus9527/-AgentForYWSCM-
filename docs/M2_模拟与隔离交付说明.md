# M2 模拟与隔离交付说明

产品：跨境电商供应链管理Agent助手  
应用版本：v0.6.0  
交付日期：2026年10月17日  
需求基线：PRD v2.0，FR11—FR15。详细结果与证据哈希见 [M2 验收摘要](M2_验收摘要.json)。

## 已实现范围

独立模拟管理入口支持生成、运行、查看报告、重放、重置及销毁。模拟管理凭据与业务账号分开；普通业务接口不接受数据库、schema 或运行空间切换参数。生成的开发数据可以在受限业务进程中打开完整工作台。

场景包括正常经营、供货延期、仓内拥堵、运输异常、销量突增、滞销、退货集中、数据延迟，以及混合压力。配置涵盖种子、版本、业务起始时间、时区、商品/仓库/商户规模、订单数量、交期、销量分布、退货率、质检率、工作日历、处理能力及故障策略。数量按基础单位整数处理。SKU 和订单数量按每商户计，经营关系和余额按实际业务生成。

每份数据从空运行空间独立生成，主数据、采购、分批收货、质检、交货、客户退货和分批调拨存在业务关联。所有库存动作调用现有应用服务；生成器不直接更新业务余额。M2 的“订单”输入驱动既有交货服务，完整销售订单状态机仍属于 M4。

开发集、固定回归集和独立验证集分别登记。固定配置位于 `simulator/scenarios/`；额外随机集使用新种子及不同参数组合，不复制开发数据库。同一控制根目录拒绝将已使用种子作为新的独立验证种子，重放和重置则保留来源关系。批量运行先登记全部案例，报告保留每一个成功或失败案例；业务验证失败可通过 `promote` 固定成回归案例。

## 隔离与生命周期

| 对象 | 实现 |
| --- | --- |
| SQLite | 每次运行独立业务数据库、投递记录、文件目录和连接池 |
| PostgreSQL | 专用模拟数据库中，每次运行独立 schema、随机密码和受限登录账号；无超级用户、建库、建角色、其他角色成员关系及 public schema 权限 |
| 业务进程 | 每次运行独立子进程，macOS 系统沙箱限制文件和网络访问；不继承模型密钥、管理数据库凭据或应用环境变量 |
| 私有事实 | 保存在控制侧单独目录；业务进程尝试读取或写入均由操作系统拒绝；不向 Agent 或业务 API 提供 |
| 状态与文件 | 会话、限流、幂等记录、时钟、投递日志、附件、备份目录和报告均属于各自运行 |
| 清理 | 仅接受登记的运行 ID 和匹配指纹；校验模拟标识、路径、不可变输入和活动进程锁；拒绝符号链接、未知路径及活动空间 |
| 重置 | 归档证据并创建新身份的后继运行；旧证据保留，旧任务无法命中新数据库 |
| 销毁 | 在无活动进程时归档输入、轨迹、私有事实及报告，再清理该运行的数据；不清理其他运行 |

控制面只存运行身份、用途、种子、状态、进度和操作审计，不存业务明细。生命周期文件锁由子进程继承，控制进程中断后，仍存活的业务进程会继续阻止误清理。PostgreSQL 的租户事务锁也加入运行指纹，避免不同 schema 内的同名商户共用一个锁。

PostgreSQL 必须使用密码认证，拒绝 `trust`/`peer` 无密码隔离方案。运行时检查账号、schema、数据库及权限；权限意外扩大时停止运行。权限设计参考 [PostgreSQL schema 权限说明](https://www.postgresql.org/docs/16/ddl-schemas.html#DDL-SCHEMAS-PRIV) 和 [角色属性说明](https://www.postgresql.org/docs/16/sql-createrole.html)。

当前进程隔离实现面向本机 macOS 的 `sandbox-exec`，已在本机实际验证。其他系统会拒绝启动受管理模拟进程；Linux/Windows 的系统隔离适配尚未交付，不会退回无隔离进程后继续报通过。

## 时间、故障和重放

业务时间按投递队列逐项推进，工作日历与处理能力影响场景事件的计划和发生时间。支持 `run --until` 暂停在指定业务时点并继续，禁止时间倒退和非有限快进量。认证有效期和耗时测量始终使用真实时间。

九类故障包括重复、乱序、延迟、丢失后补发、限流、断连、提交成功后响应超时、提交前崩溃和提交后崩溃。超时使用真实单调时钟触发；崩溃在独立业务进程内发生。冻结原业务请求及幂等键后重试，已提交操作只返回原结果。

不可变 manifest 保存用途、版本、参数、种子、代码内容哈希、运行指纹、规范化事件哈希及输出目录。投递轨迹记录事件、业务动作、尝试、故障位置、实际调度时间、结果及哈希链。重放创建新运行，使用捕获的实际投递顺序和故障安排；重新核对结果和最终数量。并发运行间不承诺真实耗时或随机业务 UUID 逐字相同。

原输入、manifest、运行身份或轨迹完整性不符时拒绝继续，不忽略损坏记录。代码变化后应建立新运行，保留旧版本及旧证据以便复查。

## 独立判定与报告

`simulator/oracle.py` 不导入被测业务模块，通过独立算术重建预期余额、采购量、在途量和记账次数，并用手工计算案例检验该判定器。私有事实另存真实事件时点、数量和已知限制因素。生成校验、业务断言、隔离结果、实际耗时、失败位置和后续尚未实现项分别输出。

业务拒绝可以是正确结果，例如超卖和跨商户写入。验收要求返回正确错误、库存不变，并保持单据、流水和 Outbox 的一致性。M3 的统一异常任务尚未交付，因此本阶段不会把“生成异常任务”标记为已完成。

| 验收集合 | 结果 |
| --- | --- |
| SQLite 全量回归 | 250 通过，1 跳过；跳过项为 PostgreSQL 专用权限漂移测试 |
| PostgreSQL 16.2 全量回归 | 249 通过，2 跳过；跳过项为 SQLite 文件备份与恢复测试 |
| 版本化固定场景 | 9 / 9 通过 |
| 额外 SQLite 随机验证 | 100 / 100 通过，9,680 项核对 |
| 额外 PostgreSQL 随机验证 | 100 / 100 通过，9,644 项核对 |
| 管理页面 | 桌面、手机、生成、运行、报告导出、重置后继空间和退出通过；无脚本错误或页面溢出 |

每套额外验证覆盖九类场景、三种销量分布、多档商品/仓库规模、质检率、退货率及处理能力；两套种子完全不同。两份数据使用相同业务编号并行执行，验证交叉文件访问、数据库读写、角色切换、错误运行投递和清理均受限制；A 重置和销毁后，B 的逻辑快照与进度保持一致。

本次机器为 macOS ARM64、8 个逻辑 CPU。随机验收为每商户 1—4 个 SKU、2—4 个仓库和 5—12 笔交货输入，2 个商户、2 个并行运行。未执行 PRD 中型/大型容量验收；不能据此宣称达到 1,000 SKU、10,000 订单的性能目标。真实数据、真实模型和外部平台未参与测试。既有 Starlette 测试客户端弃用提示仍存在。

## 使用方法

安装 `requirements-dev.txt` 后，在项目目录执行：

```sh
./scripts/simulator.sh init
./scripts/simulator.sh create --config simulator/scenarios/development.json --run-id dev-workbench
./scripts/simulator.sh run dev-workbench
./scripts/simulator.sh web --port 8020
```

打开 `http://127.0.0.1:8020/`，使用 `.local/simulator/admin-token.json` 中的本机管理凭据。独立业务工作台在另一终端启动：

```sh
./scripts/simulator.sh workbench dev-workbench --port 8021
```

业务账号为 `tenant-0-admin`，密码位于 `.local/simulator/runs/dev-workbench/business/login.json`。工作台打开期间，该空间不能再执行模拟任务或清理；关闭对应终端进程后才能继续。手工修改开发数据后，若与原模拟预期不符，应创建新数据重新验收，而不是更改期望值。

独立验证与固定回归：

```sh
.venv/bin/python scripts/verify_m2.py --root /absolute/new-regression-root --mode regression
.venv/bin/python scripts/verify_m2.py --root /absolute/new-validation-root --mode batch --count 100
```

带密码认证的 PostgreSQL 控制空间：

```sh
SIMULATOR_ROOT=/absolute/pg-simulation-root ./scripts/simulator.sh init --pg-url-file /absolute/0600-admin-url-file
SIMULATOR_ROOT=/absolute/pg-simulation-root ./scripts/simulator.sh create --scenario mixed --backend postgresql --seed 86421
```

管理 URL 文件只应用于专用本机测试实例。工具新建带专属标记的模拟数据库，再在其内部建立运行 schema。验收脚本的 `--mode postgres-suite` 可使用已有 `pgserver` 测试依赖启动独立实例、设置密码认证、执行回归及额外数据验收；停止后保留本机证据。

重放、快进和清理示例：

```sh
./scripts/simulator.sh run RUN_ID --until 2026-10-10T18:00:00+08:00
./scripts/simulator.sh replay RUN_ID
./scripts/simulator.sh report RUN_ID
./scripts/simulator.sh reset RUN_ID --fingerprint EXPECTED_FINGERPRINT
./scripts/simulator.sh destroy RUN_ID --fingerprint EXPECTED_FINGERPRINT
```

## 代码、迁移及后续范围

新增 `simulator/` 包、固定配置、独立管理页面、启动及验收脚本和 M2 测试。业务库继续使用既有第 5 版 schema，M2 不修改历史迁移或导入额外数据到原演示库；控制面使用单独的登记库。升级前保存代码和业务库快照，升级后核对原单据、余额、流水和授权数据。数据、密码、数据库和完整运行报告保留在本机，不加入 Git。

FR11 对应配置/生成及九类固定场景测试；FR12 对应种子复用拒绝、独立批量验证及分用途报告；FR13 对应并行、跨空间读写、权限漂移、活动锁、重置与清理测试；FR14 对应日历、逐事件快进、真实认证时间和独立判定；FR15 对应九类故障、真实子进程崩溃、控制进程中断恢复、源事件冲突和捕获轨迹重放。
