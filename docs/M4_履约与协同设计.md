# M4 履约与协同

本阶段承接 2026-10-24 交接基线（v0.7.0 / 迁移 1—6）。仅接入模拟渠道，真实外部回写保持关闭。

## 数量与状态

- 订单按商户、连接账号、源订单号唯一；每行保存订购、占用、发出和取消量，三者之和不得超过订购量。未分配量由差额计算。
- 每次分配产生独立履约批次，按人工选择或订单明确保存的仓库顺序执行；拣货、复核分别记录排队、开始、完成。每批可分批交接，取消只释放未发部分。
- 直接分配消耗未分配库存；渠道分配复用既有额度转换和取消回补规则。旧接口不能直接取消 M4 持有的占用；已发货只能走原单关联退货，禁止通用冲正绕过订单状态。
- 订单状态为 pending_confirmation → pending_allocation → reserved → processing → partially_shipped → shipped → completed；全部未发且取消时为 cancelled。部分取消以行数量为准。渠道完成和运输签收均为独立证据，不能代替物理发出。
- 所有库存变化仍经 inventory.movement，盘点锁、质量专属量与版本校验继续生效。业务动作、库存、事件和外发任务在同一事务中保存。

## 权限与消息

管理员维护模拟连接及账号成员；仓管负责拣货、复核、实物交接；运营负责订单确认、分配、取消和供给关联；分析岗位只读。管理员具备本商户权限；其他岗位同时受账号成员及仓库范围约束。现有店员业务维持原权限。

Inbox 先独立落库再处理。事件与业务动作分别去重，同号异内容隔离并保留原消息。缺版本或版本缺口进入待核实；旧版本不覆盖新状态。消息携带运行身份，禁止跨运行及跨商户投递。模拟源可按实体查询原事件，核实结果另存证据。

可靠外发使用新 connector_outbox；原 inventory outbox 继续保留本地库存变动记录，未配置连接的历史记录不自动发送。每个外发任务有稳定业务编号、资源内序号、真实时间租约、围栏令牌、尝试历史、退避及死信。过期租约和超时都先按原业务编号查询；只有可靠查询和幂等能力齐备时才能重发同一编号。未知或死信阻塞同资源后继任务，其他资源继续处理。人工重试不创建新业务编号。

## 对账与依赖证据

对账只保存观察值及比较报告，不覆盖余额。可靠水位下按连续序号叠加水位之后的增量，已覆盖的迟到事件不重复扣减；缺水位、缺版本、缺增量、未知本地基准均标记未知。比较保存来源时点、本地版本、输入引用、规则和差异。差异关联 M3 异常任务，关闭任务不自动改账。

订单行可显式关联采购行、调拨行或检验批次，分配与解除均追加历史。该关联表示需求依赖，不宣称已经实现批次成本或物理批号追踪；取消/发出后释放超出剩余需求的关联，并记录具体原因和数量。
