## 2 工作台变化

- 基础资料可维护供应商、供货商品、商品启停、仓库用途和来源编码映射。
- 库存总览显示经营状态、已知/未知/确认零库存和补货适用性；核实库存只能确认与账面一致的数量，不能覆盖余额。
- 收货、线下交货均必须填写来源主体与对应凭证，分批或多商品使用不同子凭证；实际发生时间可空。
- 业务事件分页查询实际发生、接收和登记时间；记录数量与单据、来源凭证。
- 首页数量按基础单位分组，未知库存不加入已确认数量或低库存提示。Agent 同步排除未知、停用及非经营对象的低库存提醒。
- 页面显示模拟环境及运行标识；待确认请求按运行、账号分开存储。店员不开放供应商、外部映射及业务事件明细。

## 3 模块边界


## 4 配置与旧接口迁移

默认 `APP_DATA_DIR` 为代码所在项目的 `.local`，SQLite 为该目录下 `inventory.db`。路径以项目根或明确的绝对配置解析，不使用调用者的工作目录。

| 配置 | 规则 |
| --- | --- |
| `APP_DATA_DIR` | 绝对路径；登录文件、备份、恢复及默认模型密钥均从这里解析 |
| `DATABASE_URL` | SQLite 或 PostgreSQL；相对 SQLite 路径明确锚定项目根 |
| `APP_RUNTIME_MODE` | development / test / simulation / production；当前业务仍只用于模拟验收 |
| `APP_RUN_ID`、`APP_TIMEZONE` | 运行身份与 IANA 时区；simulation/production 必须显式提供运行标识 |
| `APP_RUNTIME_FINGERPRINT` | 可选的预期指纹；API/Worker 与数据库错配时拒绝启动 |
| `APP_MODEL_KEY_PATH` | 绝对路径；密钥权限仍要求 0600，拒绝文件符号链接 |
| `APP_VIRTUAL_TIME` | 带时区的起始业务时间，仅 test/simulation 可用；M1 提供时钟原语，调度快进在 M2 实现 |
| `APP_EXTERNAL_WRITES` | 本版仅允许 false，未接入外部写操作 |
| `APP_ALLOW_LEGACY_RECEIPTS`、`APP_ALLOW_LEGACY_SALES` | 分别控制旧收货、交货客户端的迁移兼容；均默认 false，production 禁用 |

新版收货使用 `POST /api/v2/inventory/receipts`，线下交货使用 `POST /api/v2/inventory/sales`。`source_account` 与 `reference` 必填；一张凭证对应本次单商品到货或交货，分批或多商品应使用明确子凭证。`occurred_at` 可空，填写时须包含时区。

旧 `/api/v1/receipts/confirm` 与 `/api/v1/sales/confirm` 保留原已完成请求重放；默认拒绝新增无凭证收货/交货，分别返回 `RECEIPT_REFERENCE_REQUIRED`、`SHIPMENT_REFERENCE_REQUIRED`。旧客户端在迁移窗口显式开启兼容开关后仍可工作，但这种无凭证请求仅保证请求层幂等，不能保证业务去重。兼容响应带弃用标识，工作台已经迁移至 v2。旧回归测试显式使用兼容档位；新版默认禁用及旧请求重放有独立测试。每次重放先验证当前仓库和资源权限，即使重新登录也不能读取已撤销授权仓库的缓存结果。既有采购收货、退货、质检等凭证唯一约束继续有效，换请求键不能再次过账。

既有渠道聚合额度原值保留，不虚构来源账号。新的具名授权是单独增加的承诺，必须通过可用量校验；旧额度不能未经核对自动归到新账号。B、pending、withdrawing 等历史字段逐项保留，不以新公式重写历史流水。

## 5 迁移与恢复

1. 升级前对旧库做 SQLite 在线备份或 PostgreSQL 备份，保留原代码版本及配置。
2. 迁移 5 仅增加新表、不可变事件保护及资料来源记录，原单据、库存和流水不改写。只有既有可信期初/期初导入证据才建立已知状态；只有普通收货流水的历史组合保持未知。
3. 升级后比对旧余额、单据和流水，执行既有回归及新契约测试。
4. 指纹不匹配时拒绝直接复用数据库文件。SQLite 使用 `app.backup restore` 恢复至新文件；校验备份哈希与行数后使旧会话失效，并清除复制的运行绑定，目标在首次启动时绑定新身份。原事件的运行标识保留。
5. PostgreSQL 恢复演练在独立新库中先比对表内容哈希，再重新绑定目标。源库不改。回退使用升级前备份及对应旧代码，不提供破坏性自动降级。

本机项目已于 2026年10月16日执行迁移 5。升级前代码保存于 `.work/m1-upgrade-backups/20261016-195157/source`，SQLite 在线备份位于 `.local/backups/m1-upgrade/`。全部原业务表内容比对一致：13 条库存余额、25 张单据、25 条流水、13 条 Outbox 记录；原账号及密码保留。迁移只追加版本与管理审计，未改写原记录。详细迁移清单见同一备份目录的 `manifest.json`，验收原始报告保存在 `.local/m1-acceptance/20261016-195157/`。
