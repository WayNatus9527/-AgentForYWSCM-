# M6.1 后台分析恢复交付说明

v0.10.1 / 迁移 10，接续 [v0.10.0 流程复盘](M6_复盘与Agent交付说明.md)。本次完成常驻分析队列恢复、有限自动重试、人工重试、持久任务列表及处理记录。健康接口的业务阶段继续返回 `M6`。所有验收使用模拟数据。

## 使用方式

打开「流程复盘」，在「分析任务」查看当前任务状态、累计尝试次数和下一次自动尝试时间。刷新页面后从服务端恢复列表；点击「处理记录」查看入队、开始、中断、重试及发布记录。手机表格可横向滑动访问操作按钮。

临时分析异常自动重试；达到本轮上限或权限、业务校验失败后停止。核实故障原因并恢复相关权限或数据后，点击「重试任务」，填写原因；继续使用原任务编号与分析范围，追加历史。已完成任务只能查看报告，不提供重复执行按钮。

管理员可查看本租户任务；其他有复盘权限的岗位仅查看本人创建、且当前仍获授权的任务。管理员替他人重试时仍复查原创建人的当前权限；不会借管理员身份扩大分析范围。停用账号、撤销仓库或渠道权限后，已有缓存和幂等请求也不能绕过复查。退出后晚到的列表、报告、比较及轮询响应不会恢复上一账号的数据。

## 执行与恢复

普通开发和生产模式的 API 启动后运行恢复线程，默认每轮完成后等待 2 秒，每轮最多扫描 20 个任务。模拟工作台的 `--serve` 路径显式启用；测试及确定性模拟协议默认关闭，相关测试可显式启用。没有新增外部队列服务依赖。

- 新任务最多自动尝试 3 次，前两次失败分别等待 5 秒、30 秒。退避按累计尝试次数增长，后续轮次最多等待 120 秒。
- 人工重试追加 3 次执行额度，累计次数不清零。提交包含 `expected_attempts`、原因及幂等键，并发重复提交只入队一次。
- 每位创建人最多有 3 个排队或运行任务；人工重试同样受此限制。待执行队列按租户交错选取，避免单个租户占满一轮。
- 领取任务使用 300 秒真实时间租约；进程退出后，租约到期再恢复。运行中持有租约及尚未到退避时间的任务不会抢占。
- 临时异常回滚分析事务，存储脱敏错误码并安排下一次尝试；权限或业务校验失败立即终止。日志仅记录任务标识和异常类型，不写原始异常参数。
- 报告、明细、完成状态和完成历史在同一事务提交。提交前进程退出可接续，提交后退出不会重复发布报告。
- 一个任务失败不阻塞后续任务。扫描数据库不可用时记录 `QUEUE_UNAVAILABLE`，下轮继续；恢复线程停止后不再领取任务，最多等待正在执行的事务 10 秒。强制退出由租约接续机制处理。

租约、退避和处理历史使用真实时间；业务报表仍使用所属运行的业务时钟，模拟快进不会跳过重试等待。恢复线程按顺序处理任务，没有承诺多租户并行吞吐；耗时分析仍可能与同租户写事务争用锁。

管理员看到的后台运行状态、最近扫描时间属于**当前 API 进程**。它不代表集群心跳或租户队列统计；未启用线程的 API 进程也无法证明另一个独立 worker 是否在线。跨租户累计计数不通过该接口返回。

## API 和独立进程

新增/扩展入口均位于 `/api/v2/reviews`，请求与返回示例以 [OpenAPI](openapi.json) 为准：

| 入口 | 行为 |
| --- | --- |
| `GET /jobs?limit=20&offset=0` | 按当前身份分页列出任务 |
| `GET /jobs/{id}` | 当前状态、累计次数、额度、下次尝试、是否等待恢复 |
| `GET /jobs/{id}/history?limit=20&offset=0` | 按时间分页返回不可变处理记录 |
| `POST /jobs/{id}/retry` | 接收 `expected_attempts` 和 `reason`，返回 202；要求会话、CSRF、幂等键 |
| `GET /worker-status` | 管理员读取当前进程的恢复线程状态 |

独立 CLI 默认处理一轮；加 `--watch` 持续运行，接收 SIGTERM/SIGINT 停止。`APP_DATA_DIR` 与 `--expected-run-id` 必须显式提供，并在迁移前检查运行编号。数据库绑定指纹仍必须一致。以下仅适用于已配置的普通运行空间，所有身份、时区、数据库及模型路径配置须与 API 一致：

```sh
APP_DATA_DIR=/absolute/existing-data APP_RUN_ID=chosen-runtime \
  .venv/bin/python -m app.review_worker --expected-run-id chosen-runtime --watch
```

PostgreSQL 沿用该运行的 `DATABASE_URL` 等环境配置；不要把凭据写进文档。受管理模拟空间请使用模拟控制面的 `workbench` 命令，它负责沙箱、运行锁及指纹配置；不要对其数据库直接套用以上普通 CLI 示例。

本次未安装操作系统自动启动或故障拉起服务。API 进程运行时自动恢复分析队列，进程自身的常驻部署仍需后续工程配置。

## 升级与验收

迁移 10 在 `analysis_jobs` 增加 `attempt_limit`、`next_attempt_at`、`started_at`、`finished_at`，新增只追加的 `analysis_job_history` 和待重试索引。旧迁移 1–9 保留。已有报告和明细不重写，旧任务之前未记录的执行过程不补造历史；旧活动任务若已超过默认额度，升级时给予额外 3 次恢复额度。

使用 v0.10.0 / 迁移 9 的开发库副本完成迁移、重复迁移和备份恢复，87 张原业务表的原列及内容一致。会话、运行绑定和迁移登记按既有恢复流程处理，不计入业务表一致性数量。原 `.local/inventory.db` 未升级；升级实际运行空间前仍需按已有流程备份。DDL 已更新到 [迁移 10](schema-postgresql.sql)。
