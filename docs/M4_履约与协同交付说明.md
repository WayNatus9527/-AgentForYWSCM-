# M4 履约与协同交付说明

产品：跨境电商供应链管理Agent助手

版本：v0.8.0；数据库迁移：7；交付日期：2026-10-25

范围：PRD v2.0 的 FR06、FR16—FR18，以及本阶段所需的 FR19 事件与供给依赖证据。全部使用模拟数据，真实外部回写保持关闭。

## 工作台操作

侧栏新增「订单履约」和「模拟协同与对账」。管理员先建立模拟连接，选择仓库并授权成员。管理员拥有本商户范围；其他成员同时受岗位、连接账号和个人仓库范围限制。运营可确认、分配、取消及维护供给依赖；仓管负责拣货、复核和实物交接；分析岗位只读。旧店员业务保持原权限。

1. 在订单页直接建单，或由管理员「导入模拟订单」。导入先进入 Inbox，在协同页「处理」后才创建待确认订单。
2. 确认后按人工指定仓库或订单固定仓库顺序分配。每次分配产生独立批次，库存不足或基准未知会生成异常任务，不形成部分成功的隐性占用。使用渠道额度时指定同来源账号、仓库、商品的额度编号。
3. 每批依次开始/完成拣货及复核。实物交接填写本次凭证和数量，可分批发出；实际时间无依据时留空。
4. 取消只释放未发量。部分发出后仍可取消余量；已发部分通过既有「退货与质检」按交接单据关联退货。通用冲正和旧占用取消接口不能绕过订单状态。
5. 运输签收、渠道完成各自导入回执并进入 Inbox。渠道完成不能替代物理发货；签收和交接时间分别保存。
6. 可按明确的采购行、调拨行、检验批次编号关联需求供给。关联与解除均保存历史；取消或发货后会解除超过剩余需求的关联。该功能记录计划依赖，不代表物理批号或成本追踪。

订单按商户、连接账号、源订单号唯一。每行保存订购、占用、发出、取消数量；请求幂等、业务动作编号与交接凭证共同防止重复处理。分配、取消、实物发出都沿用统一库存事务，盘点锁与质量专属数量保护继续生效。

## 消息与外发

Inbox 在处理前独立持久化，运行身份、商户、账号和来源事件编号构成隔离与去重边界。同事件编号异内容保存为冲突证据，不覆盖原消息；业务动作另行去重。缺版本、版本缺口和无法判断的顺序保留待核实。模拟来源事实可经 `/source-facts` 登记，再通过「查询来源核实」调用适配器查询；没有事实或可靠查询能力时保持未知。

实物交接事务同时生成 connector_outbox 通知。协同页「处理下一项」可驱动模拟发送，也可运行独立 Worker。Worker 使用真实时间租约和围栏令牌，按租户、账号、业务资源排队，保存每次领取、发送、查询与结果。已领取任务过期或请求超时后，先按原业务编号查询。只有可靠查询和幂等能力允许安全重试时，才重发同一编号。不能核实时停止并生成任务；失败退避至死信，人工重试仍沿用原编号。一个资源受阻不阻塞其他资源。

API 接受请求与外部业务完成分别记录，采用至少一次传输加业务幂等。原库存 outbox 继续保留本地变动记录，历史无连接数据不自动发送。

独立 Worker 要与目标 API 使用相同数据目录、数据库和运行身份，并提供当前有效的管理员用户 ID：

```sh
APP_DATA_DIR=/absolute/business-data .venv/bin/python -m app.delivery_worker --actor-id ADMIN_USER_ID --once
```

去掉 `--once` 持续处理；每轮重新检查账号权限。受管理模拟空间必须沿用其受控环境，不得通过手改指纹或手写环境参数绕过绑定。开发工作台可直接使用页面按钮，无需额外启动 Worker。

## 快照和对账

管理员录入模拟快照，包含仓库、商品、良品/待验/残次数量、来源时间及可空覆盖水位；运营和仓管也可执行对账。可靠水位只叠加未覆盖且序号连续的观察增量，已覆盖的迟到事件不重复计入。缺水位、缺时间、未处理消息、序号缺口或本地基准未知时，报告保持未知。

报告保留原快照、增量引用、本地版本、比较时点、规则、差异及调拨在途。观察值始终与本地账分开保存，对账及关闭异常任务均不改余额。差异修复仍需明确业务动作与凭证。

## 接口、迁移和兼容

| 入口 | 用途 |
| --- | --- |
| `/api/v2/orders`、`/{id}/{action}` | 订单分页、创建及履约动作 |
| `/api/v2/connections` | 连接账号、成员与启停 |
| `/api/v2/connections/{id}/events` | 持久化来源事件 |
| `/api/v2/connections/{id}/source-facts` | 登记不可变模拟来源事实 |
| `/api/v2/inbox/{id}/{process,verify}` | 处理或查询核实消息 |
| `/api/v2/outbox/dispatch`、`/{id}/retry` | 模拟发送与原编号人工重试 |
| `/api/v2/connections/{id}/snapshots` | 保存来源快照 |
| `/api/v2/snapshots/{id}/compare` | 保存对账报告 |
| `/api/v2/connector-records/{kind}` | 分页读取消息、外发、快照与报告 |

完整请求模型见 [OpenAPI](openapi.json)，适配器接口见 [连接器契约](连接器接入契约.md)。写入保留登录、CSRF、当前权限及幂等边界；缓存回复也重新校验授权。

迁移 7 新增 20 张订单与连接器表，并为动作、历史、投递尝试、快照和增量证据安装追加保护。迁移 1—6 保持原定义。旧库在线备份后在独立副本升级、重复执行迁移并核对：50 张原业务表哈希一致；恢复至新目录通过验证，旧会话已失效。原本机业务库未升级。本轮使用另建的 M4 开发工作台，具体地址和恢复方法见 [最新交接补充](项目开发交接补充_2026-10-25.md)。

SQLite 跳过 PostgreSQL 权限漂移专用测试；PostgreSQL 跳过两项 SQLite 文件备份恢复专用测试。共同存在一项 Starlette/httpx 弃用提示，没有测试失败。确切种子、参数分布、原始报告及哈希见 [验收摘要](M4_验收摘要.json)。

M4 新增 36 个参数化后的测试案例，覆盖取消/发货竞争、事务回滚、双层去重、权限撤销、盘点锁、渠道额度、多仓分配、供给容量、乱序版本、超时外部成功、租约失效与围栏、两 Worker 竞争、退避死信和快照水位。独立数据的生成器与数量判定器不导入业务代码，另有手工金标准。验证运行采用两个隔离进程并行，每份包含两个商户；外部成功后进程真实退出的场景由控制面重新启动，再按原编号查询恢复。

```sh
# macOS；为每条命令选择新的绝对目录，保存终端日志
.venv/bin/python scripts/verify_m2.py --mode pytest --test-path tests --root /absolute/sqlite-tests
.venv/bin/python scripts/verify_m2.py --mode regression --root /absolute/fixed-regression
.venv/bin/python scripts/verify_m4.py --count 100 --root /absolute/m4-sqlite-validation
.venv/bin/python scripts/verify_m2.py --mode postgres-suite --test-path tests --count 10 --m3-count 10 --m4-count 100 --root /absolute/m4-postgresql-validation
```

受管理模拟仍依赖 macOS 沙箱；外层执行环境若禁止嵌套沙箱，应在获准的宿主进程执行上述命令，不能关闭项目隔离。pytest 夹具自建临时目录，`--root` 不代表所有 pytest 产物都位于该目录。M4 和 M3 完整流程不支持 `--until` 或捕获轨迹重放；受控重置会创建后继运行并保留失败证据。

可选浏览器复现脚本为 `scripts/verify_m4_browser.cjs`，需已安装 Playwright 和本机 Chrome，仅允许 `127.0.0.1`，只能指向可变更的独立 development 数据。参数依次为 URL、该运行的 `business/login.json`、新的输出目录。脚本创建测试订单和岗位账号，不可对验收冻结数据运行。

新增 GitHub Actions 配置在 macOS 上运行全量回归、九类固定场景及两数据库各 10 份 M4 数据，并保存报告；本轮未提交或推送，远端 CI 尚未执行。

## 后续边界

M5 的采购交期历史、供给计划、分批调拨运输和规则补货，以及 M6 的瓶颈诊断与 Agent 解释仍待实现。200 份 M4 数据不等于整版 1,000 组或中大型容量验收。当前订单列表先过滤授权再分页，尚未验证大规模查询性能；来源账号表单使用当前分页中的账号。真实渠道、海外仓、供应商协议及真实模型质量需另行验收。

开发期间的旧版本断言、嵌套沙箱限制及浏览器定位失败日志均保留在本地；最终验收使用当前代码和独立数据，未删除失败样本或更改私有预期值来制造通过。
