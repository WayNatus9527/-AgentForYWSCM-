## 本次交付

恢复线程默认 2 秒轮询、每轮最多 20 个候选；租约 300 秒，初次执行额度 3 次，自动退避 5 / 30 秒；人工重试追加 3 次额度，累计次数保留，后续退避最多 120 秒。权限和业务校验失败终止，不无限重试。报告与完成状态原子提交，历史只能追加。多个 API/worker 依靠数据库租约与事务协调，未新增操作系统进程拉起服务。

管理员查看本租户任务，其他复盘岗位查看自己的任务，所有读取与重试复查当前范围。管理员重试也不能扩大原创建人的权限。前端退出后丢弃上一账号晚到的响应。管理员的后台状态仅指当前 API 进程，跨租户累计计数不公开。

迁移 10 只新增历史表、任务重试字段和查询索引；迁移 9 数据库副本升级及重复迁移通过，87 张原业务表原列内容保留，备份恢复通过。原默认 `.local/inventory.db` 未被本轮升级。

受限模拟进程在 macOS 使用系统沙箱；在桌面代理的外层沙箱内可能需要允许启动隔离进程。PostgreSQL 流程自行创建本地临时实例与受限角色，关闭后保留数据及报告。每次使用新目录。

浏览器复现顺序：先 `prepare_review_queue_workbench.py` 生成空间并启动工作台，再依次运行 `verify_m6_browser.cjs`（登录文件参数）、`verify_review_queue_browser.cjs`（fixture JSON 参数）、`verify_review_queue_layout.cjs`（fixture JSON 参数）。三个脚本参数均为 `BASE_URL INPUT_FILE OUTPUT_DIRECTORY`；需要 Playwright 与本机 Chrome。前两个脚本会修改专用开发库；已完成的故障任务不能直接重新验收人工重试，应重新生成空间。
