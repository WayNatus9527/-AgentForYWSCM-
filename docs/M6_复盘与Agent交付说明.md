# M6 复盘与 Agent 交付说明

版本 v0.10.0，迁移 9；承接 M5。使用模拟数据验证过程复盘、时间证据订正、显式依赖诊断、改善任务及受控 Agent。最终结果与证据路径见 [验收摘要](M6_验收摘要.json)，重启与维护见 [交接补充](项目开发交接补充_M6_2026-10-25.md)。

## 使用流程

1. 进入「流程复盘」，选择仓库、可选商品/供应商/渠道连接、期间、等待预算及工作日历。日期输入明确使用 UTC；结果按仓库时区显示。截止时间不能超过当前业务时间，最长期间为 366 天。
2. 提交后台任务，页面轮询排队、执行和完成状态。报告保存生成时已知的业务输入、原事件、订正链、规则及日历。可重复打开历史报告；之后的业务变化不会重写报告。
3. 先看有效完成样本、中位数/P90/P95、未完成量、未知比例，再看候选的积压、速率、承诺偏差及实际关联订单。点击样本、订单依赖、时间线查看证据。
4. 有问题的来源时间用「订正时间证据」追加更正。原登记、接收时间与原始事件保留；再次生成报告才能看到变化。过期更正请求拒绝执行。库存登记事件不能用此入口改动。
5. 管理员/仓管可建立改善或数据核实任务，同一报告明细重复点击返回同一任务。创建任务不改库存。来源时钟异常及可信起止时间形成的负时长会自动产生可去重的数据核实任务。
6. 「比较两个报告」展示筛选、日历、规则一致性及指标变化。不同期间或业务组合仍会影响结果，比较不自动构成改善措施的因果证据。

## 指标与判断口径

| 内容 | 当前实现 |
| --- | --- |
| 粒度 | 每次到货、检验批次、履约批次、审批单；未到货采购余量按供给行 |
| 时间 | 自然小时、工作日历小时；有有效暂停/恢复证据时计算暂停与活动小时。未知实际时间不能用登记时间替代 |
| 分位数 | 仅已完成且有效的时间样本，按样本计数而非数量加权；P90/P95 使用最近秩；低于所选最低样本数标记不稳定 |
| 未完成 | 单列数量、当前等待、超期，不进入已完成分位数。旧关闭记录无法重建历史数量时标记数量未知，并从确定数量中排除 |
| 采购 | 原始承诺与该次签收前最近已登记承诺分别统计；未到货余量使用截止时已知承诺，余量关闭按事件时序重建 |
| 节点 | 运输、到货至可用、质检等待/作业/上架、审批等待、拣货与复核等待/作业、确认至实物交接、渠道完成、登记延迟 |
| 吞吐与返工 | 候选展示所选期间到达/完成数量除以期间小时；返工字段记录可见检验取消事件，不推断缺少事件的实际重复作业 |
| 依赖 | 只使用明确供给关联、履约批次及历史分配/解除；同商品或时间接近不能建立因果关系 |
| 影响 | 按订单行和时间区间去重；同一时段的关联量受未履约、未预占及可用现货约束；报告影响量为期间最大受阻量 |
| 关键路径 | 对同一显式到货/履约批次中的合法阶段边计算最长路径；并行分支不相加。缺少跨批次边时保持未知 |
| 分类 | 耗时较长、疑似瓶颈、有证据的限制、数据登记延迟、原因未知；正常长运输不能仅凭耗时判为瓶颈 |
| 排序 | 影响订单数、超期数量、未完成数量；不是概率评分，各候选影响量不能相加为总损失 |

时间预算由用户选择，用来呈现压力信号；还须有明确依赖和完整库存历史才能判为有证据的履约限制。报告同时展示「全部依赖中的最大受阻量」与「有证据的限制影响」，正常运输可以是前者而不属于后者。

工作日历保存版本、星期范围、工作时间及仓库时区。当前提供周一至周五 09–18 与全天日历，API 可指定合法班次；法定节假日、多班次及历史日历主数据管理未实现。

## 受控 Agent

复盘页的助手与分析员/运营岗位的「Agent 助手」开放四个确定性工具：解释已保存复盘、解释补货方案、跟踪采购、按所选策略生成补货方案。管理员/仓管可计算方案；分析员/运营仅可读取其授权记录。收银员无此模块权限。

没有模型密钥也能使用全部规则工具。使用模型时，仅发送当前问题、工具名和所选记录编号，模型不能更换业务记录或直接产生业务数量。模型选择歧义/不支持操作时返回澄清/不支持；请求前后均复查权限，每用户每分钟最多 6 次且同一进程内仅一个在途请求。多进程分布式限流尚未实现。

补货计算只创建不可变待确认方案，继续使用 M5 的有效期、创建者确认、输入/库存版本与权限复查。实际采购确认、收货、检验和审批仍走对应业务入口。工具执行在事务中追加审计编号、请求摘要和结果引用，短期页面问答不作为持久化证据。真实模型准确率、时延及费用未验收。

报告读取、明细读取、工具重放与改善任务都重新检查仓库及连接权限。停用连接、移除成员或收缩仓库授权会阻止继续读取受影响报告；没有用快照绕过当前权限。输入快照不包含其他仓库的采购条款或检验关联。

## 后台任务与恢复

新任务持久化后通过 FastAPI 后台执行，每位创建者最多 3 个待处理任务。工作进程取得 5 分钟真实时间租约；报告、全部明细和完成状态在同一事务发布。并发工作进程不会发布重复报告，提交前崩溃可在租约过期后重领，提交后崩溃恢复返回原报告。

普通应用部署可在与 API 完全一致的数据库、数据目录、运行编号及指纹环境下执行 `.venv/bin/python -m app.review_worker`，一次处理最多 20 个排队/过期任务。当前没有常驻调度守护进程，崩溃遗留任务须由运维触发恢复。不要在未指定目标环境时运行该命令：默认路径会指向原工作区数据库。受管理模拟空间继续由模拟控制器持有锁和启动受限工作进程，不手工改 manifest 或连接运行中的验证库。

## 交付边界

容量报告使用本机 Apple M2、8 逻辑核心、16 GiB 内存，SQLite，单客户端、均匀分配的已确认未预占订单及稀疏期初余额。通过真实建单/确认流程造数；每接口 20 次测量，含失败率、吞吐、CPU、峰值 RSS 和报表计算时间，具体数值见验收摘要。后台整版验证结束后才开始最终容量测量；浏览器及旧演示服务可能占用少量本机资源。

容量结果不等于真实混合业务、多用户并发或 PostgreSQL 容量承诺。真实外部连接、模型、生产部署、分布式限流、常驻任务调度、跨区域容灾仍需后续工程。当前额度不足与缺货可从既有业务证据查询，但复盘不自动把这些状态推断为没有显式依赖的因果瓶颈；跨批次因果边、未知历史库存及不完整实际时间继续保留缺失提示。
